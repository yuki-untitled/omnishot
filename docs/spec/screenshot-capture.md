# 自動スクリーンショットキャプチャ — iOS/Android端末の画面変化を検知して自動撮影する

## Issue
#LOCAL-002

## 目的（Why）
スマートフォンの操作マニュアル作成やアプリのエビデンス採取では、画面が切り替わるたびに手動でスクリーンショットを撮る作業が発生し、タイミングを逃したり撮り漏らしたりする負担が大きい。画面の変化を自動検知して撮影することで、この手作業と撮り漏らしを無くす。

## 実現内容（What）
- Mac OS（Apple Silicon/Intel）および Windows の両環境で動作する。
- 1つのアプリで iPhone（iOS）と Android の両方を接続してキャプチャできる。
- 複数の端末が接続されている場合に撮影する端末を選ぶ方法は、[device-selection.md](device-selection.md) を参照。
- 自動撮影には以下の2モードがあり、ユーザーが選択できる。
  - **静的モード**: 画面の変化を検知した後、指定した静止時間が経過してから撮影する。
  - **動的モード**: 画面が動いている間は撮影を待機し、画面の動きが止まった瞬間を狙って撮影する。
- 撮影された画像は、後続の [gallery.md](gallery.md) の機能でアプリの画面上に表示・管理される。
- 撮影の経過はログ欄に表示する。ログ欄には見出しを付けない。
- チェック間隔・静止待ち時間などの設定を変更しても、その内容はログ欄に表示しない（設定は変更した時点で撮影に反映される）。

## 受入基準
1. **クロスプラットフォーム起動**: Mac OS（Apple Silicon/Intel）・Windows のいずれの環境でもアプリケーションが起動し、キャプチャ機能が利用できること。
2. **iOS/Android 同時対応**: iPhone端末・Android端末のどちらを接続した場合でも、画面キャプチャが行えること。
3. **静的モードの撮影タイミング**: 静的モードでは、画面変化の検知後、指定した静止時間が経過するまで撮影が行われず、経過後に撮影されること。
4. **動的モードの撮影タイミング**: 動的モードでは、画面が動いている間は撮影が行われず、動きが止まった時点で撮影されること。
5. **ログ欄の表示**: ログ欄に「Live Logs」などの見出しが表示されないこと。設定の数値を入力・変更しても、ログ欄に設定変更の行が追加されないこと。変更した設定が、次の判定から撮影に反映されること。

## 既知の制限事項
- 実際のフレーム更新間隔が、チェック間隔より長くなる場合がある。これはアプリ側のポーリング処理ではなく、端末から画面を取得する処理自体の時間に起因する。チェック間隔や判定回数の設定を変更しても、この更新間隔より検知を速くすることはできない。
  - iOS: Appleのスクリーンショット取得サービスが端末上で画像を作る時間に依存し、画面の内容によって大きく変わる。iPhone SE（第3世代）・iOS 27.0 での実測では、画面が変化しない間は約0.1秒、設定アプリのスクロール中は約0.8秒、写真の壁紙のホーム画面では約3秒、単色に近い壁紙のホーム画面では約1秒だった。写真などの複雑な画面や、時計・ウィジェットなど少しずつ変化する部分がある画面ほど遅くなる。撮影中は単色に近い壁紙にすると改善する。この時間は go-ios 側の処理（1コマ約0.09秒）ではなく端末側で決まるため、アプリ側の修正では短縮できない。
  - Android: 約0.3秒（moto g24・USB接続での実測。端末によって異なる）。高速な取得に対応していない端末では、約1.2秒程度になる。

## 変更理由
- issue #LOCAL-002: README.md に記載されていた機能一覧のうち、自動撮影に関する仕様を `docs/spec/` に分離し、README.md は概要とリンク集に整理するため作成。
- issue #LOCAL-004: 動的モードでの誤検知調査により、iOS側の実際のフレーム更新間隔がチェック間隔より遅くなる場合があるという既知の制限事項が判明したため追記。
- issue #LOCAL-006: 実機計測（`adb exec-out screencap -p`の実行時間が約1.2秒）により、Android側にもiOSと同程度の制限事項があることが判明したため、既知の制限事項をiOS/Android共通の記述に修正。
- issue #LOCAL-007: ネイティブウィンドウ化（#LOCAL-005）に伴う表現の修正漏れ（「ブラウザ上」→「アプリの画面上」）と、既知の制限事項の文章の誤りを修正。仕様内容そのものの変更はなし。
- issue #LOCAL-014: 撮影端末の選択機能の追加に伴い、詳細仕様 [device-selection.md](device-selection.md) への参照を追記。本仕様の内容そのものの変更はなし。
- issue #LOCAL-017: ストリーム接続の一時的な切断で自動撮影全体が停止する不具合の修正に伴い、詳細仕様 [bugs/LOCAL-017_ストリーム接続の一時的な切断で自動撮影全体が停止する.md](bugs/LOCAL-017_ストリーム接続の一時的な切断で自動撮影全体が停止する.md) への参照を追記。本仕様の内容そのものの変更はなし。
- issue #LOCAL-018: 画面の縦の幅を節約するため、ログ欄の見出しを削除した。また、設定の数値を入力するたびにログ欄へ設定変更の行が流れて見づらかったため、設定変更をログに表示しないことにした。
- issue #LOCAL-019: 動的モードの判定の遅れと撮り漏れの修正に伴い、詳細仕様への参照を追記。本仕様の内容そのものの変更はなし。
- issue #LOCAL-020: Androidの画面取得を高速化し、実測で約0.3秒ごとにコマが届くようになったため、既知の制限事項をiOSとAndroidに分けて書き直した。
- issue #LOCAL-020: 画面取得の速さの調査の中で、iOSは画面の内容（写真の壁紙など）によって1コマの取得に約3秒かかることを実機で確認した。原因が端末側にあり、撮影中の壁紙で改善できることを、既知の制限事項に追記した。
