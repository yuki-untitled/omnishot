# 撮影セッションのグルーピング — 撮影の開始〜停止を1セッションとしてギャラリーで区切る

## Issue
#LOCAL-016

## 目的（Why）
現状のギャラリーは、撮影された画像がすべて単一の一覧に時系列で積み上がる。1回のアプリ起動中に複数の操作フロー（例: ログイン手順、設定変更手順など、別々の一連の操作）を順に撮影すると、どこからどこまでが1つの操作のまとまりかがギャラリー上で分からず、後から画像を選び出す・整理する作業が煩雑になる。自動撮影の開始〜停止を1つのセッションとしてギャラリー上で区切り表示することで、複数の操作フローを1回のアプリ起動でも整理しやすくする。

## 実現内容（What）
- 自動撮影の「開始」ボタンを押すたびに新しいセッションが始まり、「停止」ボタンでそのセッションが終わる。
- セッション番号は、アプリ起動後に自動撮影を開始した順に 1, 2, 3... と振る。
- ギャラリーは、セッションに属する画像をまとめ、その末尾に「未分類」の画像をまとめて表示する。セッションの区切りには見出しを挿入し、見出しには、セッション番号・開始日時・そのセッションで撮影された画像の枚数を表示する。セッション同士の順序、および各セッション・未分類グループ内の画像の順序は、ギャラリーの並び順設定（新しい順・古い順）に従う。
- 自動撮影が「撮影中」の間に [manual-capture.md](manual-capture.md) の手動撮影で保存した画像は、そのセッションに含め、見出しの枚数にも数える。
- 自動撮影を一度も開始していない状態、または自動撮影を停止した後で次のセッションを開始する前に手動撮影で保存した画像は、「未分類」として扱う。「未分類」の画像は、実際に撮影された時刻に関わらず、すべてのセッションより後ろ（一覧の末尾）に、1つの見出しへまとめて表示する。自動撮影中に確認したいセッションの画像が、単発の未分類画像によって埋もれないようにするため。
- アプリ再起動後にギャラリーへ表示される、前回起動時までに保存された既存の画像は、セッション情報を持たないため「未分類」として、同様に一覧の末尾に表示する。
- セッションの区切り（見出し・番号）は永続化しない。アプリを終了すると失われ、次回起動時はセッション番号が1から振り直される。画像ファイル自体は、従来通り [gallery.md](gallery.md) の管理下に残る。
- 全選択・個別選択・一括ダウンロード・一括削除・表示名編集は、従来通りギャラリー全体（セッションをまたいで）に対して機能する。セッション単位でのこれらの一括操作は、本仕様の対象外とする。
- セッション・未分類それぞれのグループの中では、画像本体の時系列の並び順を変更しない。

## 受入基準
1. **開始のたびに新セッション**: 自動撮影を「開始」→「停止」→再度「開始」すると、ギャラリーに2つのセッション見出しが表示され、それぞれの見出しの下に、そのセッション中に撮影された画像だけが表示されること。
2. **見出しの内容**: 各セッションの見出しに、セッション番号・開始日時・撮影枚数が表示され、枚数がそのセッションで実際に保存された画像数（自動撮影＋セッション中の手動撮影の合計）と一致すること。
3. **セッション外の手動撮影**: 自動撮影が停止中の間に手動撮影で画像を保存すると、その画像が「未分類」として、すべてのセッションより後ろ（一覧の末尾）に表示されること。
4. **起動直後の手動撮影**: 自動撮影を一度も開始していない状態で手動撮影を行うと、その画像が「未分類」として一覧の末尾に表示されること。
5. **既存画像の扱い**: アプリを再起動した後、前回起動時に保存済みだった画像がギャラリーに表示される際、「未分類」として一覧の末尾に表示されること。
6. **番号の振り直し**: アプリを再起動して自動撮影を新たに開始すると、セッション番号が1から振り直されること。
7. **グループ内の時系列順の維持**: セッション見出しが挿入されていても、各セッション・未分類それぞれのグループ内での画像本体の並び順が撮影時刻順のまま変わらないこと。
8. **未分類のまとめ**: 複数回に分けて（例: セッションとセッションの合間に複数回）未分類の画像が生まれた場合も、ギャラリーでは1つの「未分類」見出しの下にまとめて表示されること（見出しが複数回出ないこと）。
9. **一括操作の回帰**: セッション見出しがある状態でも、全選択・個別選択・一括ダウンロード・一括削除・表示名編集が、セッションをまたいで従来通り動作すること（[gallery.md](gallery.md) の受入基準）。
10. **非永続化**: セッションの区切り表示がある状態でアプリを終了し再起動すると、以前のセッションの区切り・番号が再現されないこと（画像ファイル自体は残ること）。

## 制約・関連機能
- 手動撮影の仕様は [manual-capture.md](manual-capture.md) を参照。セッション中に行った手動撮影の扱いは本仕様で定める。
- 撮影対象の端末選択は [device-selection.md](device-selection.md) を参照。本仕様は端末の選択状態には関与しない。
- 画像の一覧・一括操作・表示名編集の基本仕様は [gallery.md](gallery.md) を参照。本仕様は、その一覧に見出しによる区切りを追加するものであり、一覧・選択・操作の対象範囲は変更しない。
- ウィンドウ終了時に保存データを残さない方針（[native-window.md](native-window.md)）に合わせ、セッションの区切り情報も永続化しない。
- セッション単位での一括ダウンロード・一括削除・複数端末の同時撮影時のセッション扱いは、本仕様の対象外。

## 変更理由
- issue #LOCAL-016: 1回のアプリ起動中に複数の操作フローを撮影する際、ギャラリー上でどこからどこまでが1つのまとまりか分かりにくいという課題を受けて新規作成。
- issue #LOCAL-016: 実装当初は「未分類」を撮影時刻どおりの位置（セッションの間や前）に表示していたが、自動撮影中に未分類の画像が一覧の上部に出てきて、確認したいセッションの画像が埋もれるという指摘を受けた。「未分類」は撮影時刻に関わらず常に一覧の末尾にまとめて表示する方式に変更し、実現内容・受入基準を修正した。
