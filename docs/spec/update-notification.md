# アップデート通知 — 新しい版が公開されたことを起動時に知らせる

## Issue
#LOCAL-045

## 目的（Why）
OmniShot は GitHub Releases で配布しており、署名・公証も自動更新の仕組みも無い。利用者は、新しい版が出たことに気づく手段がなく、不具合が直った版が出ていても古い版を使い続けてしまう。新しい版があることを、アプリの画面上で知らせて、利用者が更新するきっかけを作る。

## 実現内容（What）
- 配布版のアプリは、起動したときに1回だけ、GitHub Releases（yuki-untitled/omnishot）で公開されている最新の版を確認する。確認は、起動後の画面の表示や撮影の開始を待たせない。
- 公開されている最新の版が、動いているアプリの版より新しいときは、画面の上部に通知を表示する。通知には、次を含める。
  - 新しい版の番号と、いま使っている版の番号（例: 「新しい版 v1.4.0 があります（現在 v1.3.1）」）。
  - ダウンロードページを開くボタン。押すと、その版のリリースのページを、この PC の標準のブラウザで開く。
  - 通知を閉じるボタン。押すと通知が消える。次にアプリを起動するまで、同じ通知は出ない。
- 版の新旧は、「v1.3.1」の数字3つ（メジャー・マイナー・パッチ）を順に数として比べて決める。下書き（draft）と先行版（pre-release）のリリースは、最新の版として扱わない。
- 動いているアプリの版と同じ、またはそれより古い版しか公開されていないときは、何も表示しない。
- 確認に失敗したときは、何も表示しない。失敗とは、インターネットに接続できない、10秒以内に応答がない、GitHub が確認の回数の上限などで応答を返さない、応答の内容が読み取れない、を指す。失敗しても、エラーのダイアログ・ログ欄への表示・撮影への影響は一切起こさない。
- 確認は、起動時の1回だけ行う。起動後に一定の間隔で確認し直さない。通知は、画面上部の固定する枠（[gallery.md](gallery.md)）の最上段に1行で表示し、通知の分だけ枠の高さが増える。撮影中でも表示してよく、撮影の操作・ギャラリーの操作を妨げない（部品が切れたり重なったり、操作できなくなったりしない）。
- 確認のときにインターネットへ送るのは、公開されている最新の版を問い合わせる、情報を取得するだけの通信であり、撮影した画像・端末の情報・利用者を識別する情報は送らない。
- 開発時の実行（配布版ではないもの）では、確認をしない。
- 更新は利用者が手動で行う。アプリは、新しい版のダウンロード・インストール・アプリの置き換えを自動では行わない。
- 配布版の版の番号は、そのリリースのタグ（例: v1.3.1）と一致する。

## 受入基準
1. **新しい版があるとき**: アプリより新しい版が公開されている状態（試験用に、アプリの版を実際の最新より古い版にした状態）で起動すると、画面の上部に、新しい版の番号と現在の版の番号を示した通知が表示されること。
2. **ダウンロードページを開く**: 通知のボタンを押すと、新しい版のリリースのページが標準のブラウザで開くこと。アプリ内のウィンドウでは開かないこと。
3. **通知を閉じる**: 閉じるボタンを押すと通知が消え、同じ起動中は再び表示されないこと。アプリを起動し直すと、再び表示されること。
4. **最新のとき**: アプリの版が公開されている最新の版と同じ、またはそれより新しいときは、通知が表示されないこと。
5. **版の比べ方**: 「v1.10.0」は「v1.9.0」より新しい版と判定されること（文字列の並びではなく、数として比べること）。
6. **下書き・先行版**: 下書きまたは先行版のリリースだけが新しい版であるときは、通知が表示されないこと。
7. **確認に失敗したとき**: インターネットに接続していない状態で起動しても、通知・エラーのダイアログ・ログ欄の表示が何も出ず、通常どおり撮影できること。応答が10秒以内に返らない場合も同じであること。
8. **起動を待たせない**: 確認の応答が遅い状態（10秒かかる状態）でも、画面の表示・端末の検出・撮影の開始が、確認を待たずに行えること。
9. **通信の内容**: 確認の通信が、最新の版を問い合わせる取得のみで、画像・端末の情報を送らないこと。起動後に、確認の通信が2回以上行われないこと。
10. **開発時の実行**: 開発時の実行（配布版ではないもの）で起動したとき、確認の通信が行われず、通知が表示されないこと。
11. **操作を妨げない**: 通知の表示中も、撮影の開始・停止、ギャラリーの操作が従来どおりできること。通知が表示されたときに、撮影の設定欄・ギャラリーの操作バーの部品が、切れたり重なったりしないこと（ウィンドウの下限の大きさ 幅940px・高さ600px でも同じ）。
12. **版とタグの一致**: リリースの手順（[../guides/build.md](../guides/build.md)）で作った配布物の版の番号が、タグと一致していること。

## 制約・関連機能
- 配布方法は [../guides/build.md](../guides/build.md) のリリース手順を参照。ウィンドウの大きさの下限は [native-window.md](native-window.md)、固定する上部の枠は [gallery.md](gallery.md) を参照。
- 自動更新（ダウンロードからアプリの置き換えまで）は、Mac で署名・公証を受けていない現状では扱いが難しいため、この仕様の対象外とする。
- 確認をしない設定・確認の間隔の設定は設けない。

## 変更理由
- issue #LOCAL-045: 「今後追加した方がいい機能」の検討で、配布版を GitHub Releases で配っているため、新しい版があることを知らせるだけでも役立つという提案があり、追加することにした。動きは、ユーザーが「起動時に確認して画面に表示」を選んだ。確認のボタンによる手動の確認と、自動ダウンロード・自動更新は、今回は対象外とした。
