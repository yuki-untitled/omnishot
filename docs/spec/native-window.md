# ネイティブウィンドウ化 — アプリをブラウザ別窓ではなくネイティブウィンドウで表示する

## Issue
#LOCAL-005

## 目的（Why）
これまでアプリはシステムのデフォルトブラウザにタブを開く方式で起動していたため、他のブラウザタブと混在して見失いやすく、デスクトップアプリとして自己完結した見た目・操作感になっていなかった。ネイティブウィンドウとして表示することで、独立したアプリケーションとしての体験を提供する。

## 実現内容（What）
- アプリ起動時、システムのデフォルトブラウザではなく、専用のネイティブウィンドウが開く。
- ウィンドウのタイトルバーの閉じるボタンでウィンドウを閉じると、既存の「アプリ終了」ボタンと同じ後始末（撮影データの一時フォルダ削除、iOS/Android関連の一時ファイル削除）が行われ、アプリケーションプロセスが終了する。
- 画面上に表示される内容（キャプチャ機能・[gallery.md](gallery.md)のギャラリー機能など）は従来と同一で、表示方法のみが変わる。
- 画面上部のアプリ名（OmniShot）の左に、絵文字ではなくアプリのアイコン画像を表示する。

## 受入基準
1. **ネイティブウィンドウでの起動**: アプリを起動すると、ブラウザのタブではなく専用のウィンドウが開き、アプリのUIが表示されること。
2. **ウィンドウを閉じた際の後始末**: ウィンドウの閉じるボタンでウィンドウを閉じると、撮影データの一時フォルダ・iOS関連の一時ファイルが削除され、アプリケーションプロセスが終了すること。
3. **既存機能の回帰**: 自動撮影・ギャラリー表示・表示名編集など、ウィンドウ化以前から存在する機能が引き続き正常に動作すること。
4. **Mac/Windows双方での動作**: Mac OS（Apple Silicon/Intel）・Windowsのいずれの環境でも、ネイティブウィンドウとして正しく起動すること。
5. **画面上部のアイコン**: 画面上部のアプリ名の左に、絵文字（📱）ではなくアプリのアイコン画像が表示されること。

- ビルド時の前提条件（Windowsの WebView2 Runtime 等）は [../guides/build.md](../guides/build.md) を参照。

## 変更理由
- issue #LOCAL-005: 「ブラウザ別窓であることのUX上の不便さ」というユーザーからの課題提起を受け、ネイティブウィンドウ化の仕様として新規作成。Mac上での実ビルド・起動・ウィンドウを閉じた際の後始末までは実機確認済み。Windows側の実機確認は未実施。
- issue #LOCAL-018: 画面上部のアプリ名の表示を、ウィンドウやDockのアイコンと見た目をそろえるため、絵文字からアプリのアイコン画像に変更した。
