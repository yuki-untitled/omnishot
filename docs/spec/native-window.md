# ネイティブウィンドウ化 — アプリをブラウザ別窓ではなくネイティブウィンドウで表示する

## Issue
#LOCAL-005

## 目的（Why）
これまでアプリはシステムのデフォルトブラウザにタブを開く方式で起動していたため、他のブラウザタブと混在して見失いやすく、デスクトップアプリとして自己完結した見た目・操作感になっていなかった。ネイティブウィンドウとして表示することで、独立したアプリケーションとしての体験を提供する。

## 実現内容（What）
- アプリ起動時、システムのデフォルトブラウザではなく、専用のネイティブウィンドウが開く。
- ウィンドウのタイトルバーの閉じるボタンでウィンドウを閉じると、既存の「アプリ終了」ボタンと同じ後始末（撮影データの一時フォルダ削除、iOS/Android関連の一時ファイル削除）が行われ、アプリケーションプロセスが終了する。
- 終了時の後始末では、iOS 17 以降の端末との通信に使う go-ios の常駐トンネル（エージェント）も止める。止めないと、アプリを終了した後もトンネルが動き続け、go-ios を更新しても古い版のトンネルが使われ続けたり、端末の古い接続が残ったりするため。次にアプリで iOS 端末を使うときは、トンネルが自動で起動する。
- 終了時の後始末では、Android 端末との通信に使う adb サーバーも止める。iOS のトンネルと同じく、アプリを終了した後に常駐し続けないようにするため。adb サーバーは PC に1つで、ほかのツール（Android Studio など）と共有されているため、それらを同時に使っている場合は、そのツールと端末の接続も一時的に切れる（そのツールが adb サーバーを起動し直すと戻る）。
- adb サーバーが止まっている状態でアプリを起動すると、端末の一覧を検出するときに adb サーバーが自動で起動する。起動した直後は端末の認識が間に合わないことがあるため、adb サーバーを起動した直後に Android 端末が1台も見つからなかった場合は、1秒待ってもう一度だけ検出する。
- アプリの起動直後など、トンネルが起動途中のときに撮影（自動撮影・手動撮影）を始めて失敗した場合は、トンネルの準備ができるのを待ってから（最大10秒）1回だけやり直す。待っていることはログに表示する。
- 画面上に表示される内容（キャプチャ機能・[gallery.md](gallery.md)のギャラリー機能など）は従来と同一で、表示方法のみが変わる。
- 画面上部のアプリ名（OmniShot）の左に、絵文字ではなくアプリのアイコン画像を表示する。

## 受入基準
1. **ネイティブウィンドウでの起動**: アプリを起動すると、ブラウザのタブではなく専用のウィンドウが開き、アプリのUIが表示されること。
2. **ウィンドウを閉じた際の後始末**: ウィンドウの閉じるボタンでウィンドウを閉じると、撮影データの一時フォルダ・iOS関連の一時ファイルが削除され、アプリケーションプロセスが終了すること。
3. **既存機能の回帰**: 自動撮影・ギャラリー表示・表示名編集など、ウィンドウ化以前から存在する機能が引き続き正常に動作すること。
4. **Mac/Windows双方での動作**: Mac OS（Apple Silicon/Intel）・Windowsのいずれの環境でも、ネイティブウィンドウとして正しく起動すること。
5. **終了時にトンネルを止める**: iOS 端末で撮影した後に「アプリ終了」ボタン、またはウィンドウの閉じるボタンでアプリを終了すると、go-ios の常駐トンネルのプロセスが残っていないこと。再びアプリを起動すると、iOS 端末を検出して撮影できること。起動してすぐに「自動撮影」または「手動撮影」を押した場合も、ログに「トンネルの起動を待っています」旨が表示された後、撮影できること。
6. **画面上部のアイコン**: 画面上部のアプリ名の左に、絵文字（📱）ではなくアプリのアイコン画像が表示されること。
7. **終了時に adb サーバーを止める**: Android 端末で撮影した後にアプリを終了すると、adb サーバーのプロセスが残っていないこと。再びアプリを起動すると、Android 端末が一覧に表示され（起動直後の1回目の検出で）、撮影できること。

## 制約・関連機能
- Web UI本体の機能は [screenshot-capture.md](screenshot-capture.md)・[gallery.md](gallery.md) を参照。
- go-ios のトンネル用の識別情報は、ユーザーごとのアプリ用フォルダ（Mac: `~/Library/Application Support/OmniShot`、Windows: `%APPDATA%\OmniShot`）に保存する。Finder から起動したアプリは、作業フォルダに書き込めないため（[LOCAL-032](bugs/LOCAL-032_アプリ化するとiOSのトンネルが起動できずトンネルの起動が連鎖し続ける.md)）。終了時の後始末では消さない。
- ビルド時の前提条件（Windowsの WebView2 Runtime 等）は [../guides/build.md](../guides/build.md) を参照。

## 変更理由
- issue #LOCAL-005: 「ブラウザ別窓であることのUX上の不便さ」というユーザーからの課題提起を受け、ネイティブウィンドウ化の仕様として新規作成。Mac上での実ビルド・起動・ウィンドウを閉じた際の後始末までは実機確認済み。Windows側の実機確認は未実施。
- issue #LOCAL-018: 画面上部のアプリ名の表示を、ウィンドウやDockのアイコンと見た目をそろえるため、絵文字からアプリのアイコン画像に変更した。
- issue #LOCAL-026: アプリを終了しても go-ios の常駐トンネルが動き続け、go-ios の更新後も古い版のトンネルが使われ続けた（iOS の画面取得が遅いままだった）ことを受け、終了時の後始末でトンネルも止めることにした。
- issue #LOCAL-026: 実装の際、トンネルを止めた直後に撮影を始めると、トンネルの準備ができる前に接続しようとして失敗することを実機で確認した。アプリを終了するとトンネルが止まるため、次の起動直後に起きやすい。失敗したときにトンネルの準備を待ってやり直すことを追記した。実機（iPhone SE 第3世代・iOS 27.0・go-ios 1.3.2）で、トンネルを止めた直後の自動撮影・手動撮影がそれぞれ2回とも約3秒で成功し、トンネルが動いている通常時は待たずに始まることを確認した。
- issue #LOCAL-026: アプリ上で、「アプリ終了」を押すと go-ios のトンネルのプロセスが残らないこと、再び起動して iOS 端末で撮影できることをユーザーが確認した（起動時の端末の検出でトンネルの準備が先に終わるため、「トンネルの起動を待っています」の表示は出なかった）。
- issue #LOCAL-029: iOS のトンネル（LOCAL-026）と同じく、アプリの終了後も adb サーバーが常駐し続けていたため、終了時の後始末で止めることにした。止めた後の起動直後に端末の認識が間に合わない場合に備え、adb サーバーを起動した直後に端末が見つからなければ1回だけ検出し直すことにした。
- issue #LOCAL-029: アプリ上で、Android 端末で撮影した後にアプリを終了すると adb サーバーのプロセスが残らないことを確認した。
- issue #LOCAL-030: 同じ確認の際、トンネルが動いていない状態（Android 端末だけを使った場合）で終了すると、トンネルを止める命令が go-ios のトンネルを起動してしまい、終了後に残ることが分かった。[LOCAL-030](bugs/LOCAL-030_終了時にiOSのトンネルが動いていないとトンネルが起動して残る.md) で修正した。
- issue #LOCAL-029: アプリ上で、adb サーバーを止めた後に起動し直すと、最初の検出で Android 端末が一覧に表示され、撮影できることをユーザーが確認した。
- issue #LOCAL-030: アプリ上で、Android 端末だけを使ってアプリを終了した後、go-ios のトンネルと adb サーバーのプロセスが残らないことを確認した。
- issue #LOCAL-032: Finder から起動した .app で iOS のトンネルが起動できず、トンネルの起動が連鎖し続けた。トンネル用の識別情報の保存先をユーザーごとのアプリ用フォルダにした（[LOCAL-032](bugs/LOCAL-032_アプリ化するとiOSのトンネルが起動できずトンネルの起動が連鎖し続ける.md)）。
