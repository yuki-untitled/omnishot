# バグ修正: iOS のトンネルに古い接続が残ると撮影を開始できず、失敗の理由も表示されない

## Issue
#LOCAL-025

## 不具合現象と再現手順（Why）
### 発生している現象
iOS 端末で「自動撮影」を押すと、次のログが出て撮影が始まらないことがある。

```
📱 iOS ストリーム接続を開始します...
❌ iOSストリームの起動に失敗しました（go-iosが終了コード1で終了しました）。
```

何度押しても同じ結果になり、アプリの操作では直らない。表示されるのは終了コードだけで、原因が分からない。

実機での調査では、go-ios は次の理由で終了していた。

```
{"level":"ERROR","msg":"could not connect to RSD, host fd03:f3d2:22b2::1, port 59940","err":"... ConnectUserSpaceTunnel: failed to dial: dial tcp 127.0.0.1:60107: connect: connection refused"}
```

iOS 17 以降では、端末との通信は常駐するトンネル（go-ios のエージェント）を通る。このトンネルに、端末の古い接続（実際には使えない中継の口）が残っていた。トンネルを止めて起動し直すと、撮影できるようになった。

また、LOCAL-017 で追加した「go-ios が出したエラーの理由を、切断時のメッセージに反映する」仕組みが、go-ios 1.3.2 に更新した後は働いていない。go-ios 1.3.2 では、エラーの記録の `level` が `"error"`・`"fatal"` から `"ERROR"` などの大文字に変わったため。

### 再現手順
1. iOS 端末を接続し、自動撮影ができることを確認して停止する
2. 端末のケーブルを抜き、しばらくしてから挿し直す（トンネルに古い接続が残る。必ず再現するとは限らない）
3. 「自動撮影」を押す
   - 期待値: アプリがトンネルを起動し直して撮影を始める。起動し直しても撮影できない場合は、go-ios が出した理由を含むメッセージが表示される
   - 実際: 「go-iosが終了コード1で終了しました」とだけ表示され、撮影が始まらない。何度押しても同じ

## 修正内容（What）
### 根本原因
1. トンネルに端末の古い接続が残ると、go-ios が端末に接続できずに終了する。アプリには、この状態から立ち直る仕組みがなかった。
2. 撮影の開始に失敗したときのメッセージは終了コードだけで、go-ios が出した理由を使っていなかった。
3. go-ios のエラーの記録を小文字の `level`（`"error"`・`"fatal"`）でだけ判定しており、go-ios 1.3.2 の大文字の記録を読み取れていなかった。

### 修正方針
- go-ios のエラーの記録は、`level` の大文字・小文字を区別せずに読み取る。
- iOS の撮影の開始に失敗したときは、go-ios が出したエラーの理由をメッセージに含める。理由が得られない場合は、従来どおり終了コードを表示する。
- go-ios が「トンネルを通して端末に接続できない」という理由で失敗した場合（自動撮影の開始、手動撮影の1回だけの取得のどちらも）、アプリがトンネルを止めて起動し直し、1回だけやり直す。やり直しても失敗した場合は、理由を含むメッセージを表示して撮影しない。
- トンネルを起動し直すときは、端末の新しい接続ができるまで待ってからやり直す（止めた直後は古い接続が残っており、すぐにやり直すと同じ理由で失敗するため）。待つのは最大10秒とする。
- トンネルを起動し直したことは、ログに表示する（ユーザーが待ち時間の理由を分かるようにするため）。
- それ以外の理由の失敗では、トンネルを起動し直さない（従来どおり）。

## 受入基準（再発防止・回帰テスト）
1. **古い接続からの自動復旧**: トンネルに古い接続が残った状態（go-ios が「could not connect to RSD」で失敗する状態）で「自動撮影」を押すと、ログに「トンネルを起動し直します」旨が表示され、その後に撮影が始まること。
2. **手動撮影での自動復旧**: 同じ状態で、自動撮影を停止中に「手動撮影」を押すと、トンネルを起動し直したうえで1枚保存されること。
3. **やり直しは1回だけ**: トンネルを起動し直しても接続できない場合は、やり直しを繰り返さず、go-ios が出した理由を含むメッセージが表示され、撮影されないこと。
4. **失敗の理由の表示**: iOS の撮影の開始に失敗したとき、メッセージに go-ios が出したエラーの理由（例: 「could not connect to RSD ...」）が含まれること。
5. **大文字のエラーの記録**: go-ios 1.3.2 で撮影中に go-ios がエラーを出して切断した場合、その理由が切断時のメッセージに反映されること（[LOCAL-017](LOCAL-017_ストリーム接続の一時的な切断で自動撮影全体が停止する.md) の受入基準9）。
6. **回帰**: 通常の状態では、トンネルを起動し直さずに従来どおり撮影が始まること。Android の撮影に影響がないこと。Live Logs に go-ios の出力そのものが流れないこと（[LOCAL-017](LOCAL-017_ストリーム接続の一時的な切断で自動撮影全体が停止する.md) の受入基準10）。

## 変更理由
- issue #LOCAL-025: 実機で「go-iosが終了コード1で終了しました」と表示されて撮影を開始できない不具合を確認した。調査の結果、トンネルに端末の古い接続が残っていたこと、go-ios 1.3.2 でエラーの記録の書き方が変わり LOCAL-017 の仕組みが働いていなかったことが分かり、新規作成。
- issue #LOCAL-025: 実装の際、トンネルを止めた直後は古い接続先がしばらく残り、すぐにやり直すと同じ理由で失敗することを実機で確認した。端末の新しい接続ができるまで待ってからやり直す方針を追記した。実機（iPhone SE 第3世代・iOS 27.0・go-ios 1.3.2）で、トンネルを起動し直してから自動撮影の開始（4回）・手動撮影（2回）がすべて成功し、約3〜4秒で撮影できることを確認した。古い接続が残った状態そのものは意図して作れないため、その状態からの復旧はアプリ上で今後確認する。
- issue #LOCAL-025: アプリ上での確認の時点では、トンネルに古い接続が残る状態は再現しなかった。受入基準1〜3（古い接続からの自動復旧）は、再現したときに確認する。
