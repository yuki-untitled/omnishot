# バグ修正: アプリ化するとスクリーンショットをダウンロードできない

## Issue
#LOCAL-033

## 不具合現象と再現手順（Why）
### 発生している現象
ビルドしたアプリ（Mac の .app・Windows の exe）で、ギャラリーの「選択した画像をダウンロード」を押しても、ZIP が保存されない。保存ダイアログも出ず、エラーの表示もない。撮影した画像は終了時に削除されるため（[native-window.md](../native-window.md)）、ユーザーは撮影結果を持ち出せない。

### 再現手順
1. ビルドしたアプリを起動し、端末を選んで撮影する。
2. ギャラリーで画像を1枚以上選択する。
3. 「ダウンロード」を押し、ZIP ファイル名を入力して確定する。
4. 期待値: ファイルの保存先を選ぶダイアログが開き、ZIP が保存される。実際: 何も起きず、ZIP は保存されない。

## 修正内容（What）
### 根本原因
アプリのウィンドウ（pywebview）は、ダウンロードの許可設定が初期状態では無効になっている（pywebview 6.2.1 の `ALLOW_DOWNLOADS` の初期値は無効）。画面側はリンクのクリックでダウンロードさせているが、ウィンドウがそのダウンロード要求を取り消すため、保存が行われない。ブラウザで開いた場合は、ブラウザ自身のダウンロード機能が働くため発生しない。

### 修正方針
- アプリのウィンドウでダウンロードを許可する。
- ダウンロードすると、OS の保存先選択ダイアログが開き、ユーザーが保存先とファイル名を選んで保存できる状態にする（ダイアログの初期の保存先はユーザーのダウンロードフォルダ）。
- 画面側の ZIP ファイル名の入力・ZIP 内のファイル名の規則（[gallery.md](../gallery.md)、[LOCAL-001](LOCAL-001_表示名機能の未整合.md)）は変えない。

## 受入基準（再発防止・回帰テスト）
1. **再現手順の検証**: ビルドしたアプリで再現手順を実行すると、保存先選択ダイアログが開き、選んだ場所に入力した名前の ZIP が保存されること。
2. **ZIP の内容**: 保存した ZIP を開くと、選択した画像がすべて含まれ、ファイル名が従来と同じ規則（表示名を反映）であること。
3. **キャンセル**: 保存先選択ダイアログでキャンセルすると、ファイルは作られず、アプリの操作を続けられること。
4. **Mac/Windows双方**: Mac（Apple Silicon）と Windows のビルドで、1〜3 を満たすこと。
5. **回帰**: ギャラリーの選択・一括削除・表示名編集、および終了時の後始末が従来どおり動作すること。
