# バグ修正: 動的モードで、判定回数が設定より1回少なく扱われる組み合わせがある

## Issue
#LOCAL-022

## 不具合現象と再現手順（Why）
### 発生している現象
動的モード（[screenshot-capture.md](../screenshot-capture.md)）で、チェック間隔と判定回数の組み合わせによっては、設定した判定回数より1回少ない「📊 静止確認」で撮影される。たとえば、チェック間隔0.7秒・判定回数3回では、「📊 静止確認: 1/2」「2/2」と表示され、2回で撮影される。ユーザーが設定した回数より早く撮影されるので、止まりきっていない画面を撮る可能性が上がる。

画面で入力できる組み合わせ（チェック間隔0.1〜30秒を0.1秒刻み × 判定回数1〜10回の3,000通り）のうち、103通りで1回少なくなる。多くなる組み合わせはない。チェック間隔1秒以下では、0.7秒×3回と0.7秒×6回の2通りが該当する。

### 再現手順
1. 端末（iOS または Android）を接続し、動的モード・チェック間隔0.7秒・判定回数3回で自動撮影を開始する
2. 画面を操作してから止める
3. ログを確認する
   - 期待値: 「📊 静止確認: 1/3」「2/3」「3/3」の3回の後に撮影される
   - 実際: 「📊 静止確認: 1/2」「2/2」の2回の後に撮影される

## 修正内容（What）
### 根本原因
- 画面からサーバーへは、判定回数そのものではなく「チェック間隔 × 判定回数」の秒数を送っている。サーバーはこの秒数をチェック間隔で割って、判定回数に戻している。
- 小数の計算には誤差があるため、割り算の結果がわずかに小さくなる組み合わせがある（例: 0.7 × 3 ÷ 0.7 = 2.9999…）。サーバーは小数点以下を切り捨てて回数にするため、1回少なくなる。

### 修正方針
- 動的モードの判定回数は、画面で設定した回数とつねに一致させる。小数の計算の誤差で回数が変わらないようにする。
- 静的モードの静止待ち時間（秒）の扱いは変更しない。
- 画面の設定項目・入力範囲は変更しない。

## 受入基準（再発防止・回帰テスト）
1. **再現手順の検証**: 再現手順1〜3を行ったとき、「📊 静止確認」が 1/3・2/3・3/3 と表示され、3回の後に撮影されること。
2. **全組み合わせ**: チェック間隔0.1〜30秒（0.1秒刻み）と判定回数1〜10回のすべての組み合わせで、動的モードの判定に使われる回数が、画面で設定した判定回数と一致すること。
3. **回帰（静的モード）**: 静的モードの撮影タイミング（静止待ち時間の秒数）が従来どおりであること（[screenshot-capture.md](../screenshot-capture.md) の受入基準3）。
4. **回帰（設定の反映）**: 撮影中にチェック間隔・判定回数を変更したとき、従来どおり次の判定から反映されること。
