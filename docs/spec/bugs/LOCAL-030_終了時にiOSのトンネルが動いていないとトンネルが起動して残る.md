# バグ修正: 終了時に iOS のトンネルが動いていないと、トンネルが起動して残る

## Issue
#LOCAL-030

## 不具合現象と再現手順（Why）
### 発生している現象
アプリを終了した後に、go-ios の常駐トンネル（`go-ios tunnel start --userspace`）のプロセスが残ることがある。[native-window.md](../native-window.md) の「終了時の後始末でトンネルも止める」（LOCAL-026）に反する。

LOCAL-029 の確認で、Android 端末だけを使ってアプリを終了したところ、終了した時刻に起動したトンネルのプロセスが残っていた。

### 再現手順
1. go-ios のトンネルが動いていない状態でアプリを起動する（例: iOS 端末を接続せず、Android 端末だけを使う）
2. 「アプリ終了」ボタン、またはウィンドウの閉じるボタンでアプリを終了する
3. go-ios のトンネルのプロセスを確認する
   - 期待値: トンネルのプロセスが無い
   - 実際: 終了した時刻に起動したトンネルのプロセスが残っている

## 修正内容（What）
### 根本原因
go-ios（1.3.2）でトンネルを止める命令は、「トンネルを自動で起動する」設定（`ENABLE_GO_IOS_AGENT`）を付けて送ると、トンネルが動いていない場合に、まずトンネルを起動してしまう。そのうえで止める要求の送り先を誤って失敗するため、起動したトンネルが残る。アプリは終了時にこの設定を付けて止める命令を送っていた。

実機（Mac・go-ios 1.3.2）で、次のことを確認した。
- 設定を付けた場合: トンネルが動いているときは止まる。動いていないときは、トンネルが起動して残る。
- 設定を付けない場合: トンネルが動いているときは止まる。動いていないときは、何も起動しない。

### 修正方針
- トンネルを止める命令は、トンネルを自動で起動する設定を付けずに送る。トンネルが動いていない場合は、何も起動しない。
- 撮影の失敗から立ち直るためにトンネルを起動し直す処理（[LOCAL-025](LOCAL-025_iOSのトンネルに古い接続が残ると撮影を開始できず理由も表示されない.md)）の動きは変えない。止めた後にトンネルが起動するのを待つ動きも、従来どおりとする。

## 受入基準（再発防止・回帰テスト）
1. **トンネルが動いていないときの終了**: iOS 端末を使わずに（トンネルが動いていない状態で）アプリを終了すると、go-ios のトンネルのプロセスが残っていないこと。
2. **トンネルが動いているときの終了**: iOS 端末で撮影した後にアプリを終了すると、トンネルのプロセスが残っていないこと（[native-window.md](../native-window.md) の受入基準5）。
3. **回帰（トンネルの起動し直し）**: トンネルを起動し直して撮影を始める処理が、従来どおり動くこと（[LOCAL-025](LOCAL-025_iOSのトンネルに古い接続が残ると撮影を開始できず理由も表示されない.md) の受入基準1〜3）。
4. **回帰（終了後の起動）**: 終了した後にアプリを起動し直すと、iOS 端末・Android 端末を検出して撮影できること。
