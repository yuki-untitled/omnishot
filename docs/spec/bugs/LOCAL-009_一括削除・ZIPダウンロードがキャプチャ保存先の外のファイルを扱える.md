# バグ修正: 一括削除・ZIPダウンロードで、キャプチャ保存先の外のファイルを指定できてしまう

## Issue
#LOCAL-009

## 不具合現象と再現手順（Why）
### 発生している現象
[gallery.md](../gallery.md) の一括削除・ZIPダウンロードは、リクエストで受け取ったファイル名を検証せずに保存先フォルダ（`captures/`）と結合して扱っている。`../` を含む名前を指定すると、保存先フォルダの外にあるファイルを削除したり、ZIPに含めてダウンロードしたりできる。同じギャラリーの表示名変更は、ファイル名に区切り文字を含む場合に拒否しており、扱いが揃っていない。

### 再現手順
1. アプリを起動する
2. 削除API（`/delete_selected`）に、`{"filenames": ["../<保存先の外のファイル名>"]}` をPOSTする
3. 期待値・実際の差異
   - 期待値: 不正なファイル名として拒否され、保存先の外のファイルは変更されない
   - 実際: 保存先の外のファイルが削除される（ZIPダウンロード（`/download_selected`）でも同様に、保存先の外のファイルがZIPに含まれる）

## 修正内容（What）
### 根本原因
- 削除・ZIPダウンロードの両処理が、受け取ったファイル名がディレクトリ区切りを含まない単純なファイル名であることを確認していない（表示名変更の処理にだけ確認がある）

### 修正方針
- 保存先フォルダ直下の単純なファイル名のみを受け付ける
- ディレクトリ区切りを含むなど、単純なファイル名でないものが1件でも含まれる場合は、リクエスト全体を不正なリクエストとして拒否し、削除・ZIP作成のいずれも行わない
- 正当なファイル名のみのリクエストは、従来と同じ結果になる

## 受入基準（再発防止・回帰テスト）
1. **削除の拒否**: `/delete_selected` に `../` を含むファイル名を1件でも含めてPOSTすると、不正なリクエストとして拒否され、保存先の外のファイルも、同じリクエストに含まれる正当なファイルも削除されないこと。
2. **ZIPダウンロードの拒否**: `/download_selected` に `../` を含むファイル名を1件でも含めてPOSTすると、不正なリクエストとして拒否され、ZIPが生成されないこと。
3. **回帰（一括削除）**: ギャラリーで選択した正当なキャプチャ画像を一括削除すると、従来通り削除され、対応する表示名も取り除かれること。
4. **回帰（ZIPダウンロード）**: 表示名を変更した画像を含めてZIPダウンロードすると、従来通りZIP内のファイル名に表示名が反映されること（[gallery.md](../gallery.md) 受入基準6・7）。

- [LOCAL-001_表示名機能の未整合.md](LOCAL-001_表示名機能の未整合.md) — 表示名変更側のファイル名検証
