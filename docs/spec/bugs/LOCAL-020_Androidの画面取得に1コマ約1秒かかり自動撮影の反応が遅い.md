# バグ修正: Android の画面取得に1コマ約1秒かかり、自動撮影の反応が遅い

## Issue
#LOCAL-020

## 不具合現象と再現手順（Why）
### 発生している現象
Android 端末で自動撮影をすると、端末から新しい画面（コマ）が届く間隔が約1.2秒になる。変化の判定はコマが届くたびに行うため、画面を操作してから判定されるまで、また操作を止めてから撮影されるまでが遅い。動的モード・判定回数3回では、[LOCAL-019](LOCAL-019_動的モードで操作を止めてから撮影までが遅く連続した操作で撮り漏れる.md) の修正後も、操作を止めてから撮影まで約5秒かかる。

実機（moto g24、USB 接続）での計測結果:

| 取得方法 | 1コマの取得にかかる時間 |
|---|---|
| 現在（端末上で PNG に圧縮して取得） | 約1.27秒 |
| 圧縮せずに取得（raw） | 約0.64秒 |
| 圧縮せずに取得し、2つの取得を並行 | 約0.3秒ごとに1コマ |
| 圧縮せずに取得し、3つの取得を並行 | 約0.25秒ごとに1コマ（2つからほぼ改善しない） |

### 再現手順
1. Android 端末を接続し、動的モード・チェック間隔0.1秒・判定回数3回で自動撮影を開始する
2. 画面をスクロールして止める
3. ログを確認する
   - 期待値: 「📊 静止確認」のログが約0.3秒間隔で進み、操作を止めてから約2秒で撮影される
   - 実際: 「📊 静止確認」のログが約1秒間隔で進み、操作を止めてから撮影まで約5秒かかる

## 修正内容（What）
### 根本原因
- Android の画面取得で、毎回端末上で画面を PNG に圧縮してから受け取っている。圧縮の処理が重く、1コマの取得に約1.2秒かかる。
- 画面の取得を1つずつ順番に行っているため、1コマの取得時間がそのままコマの届く間隔になる。

### 修正方針
- Android の自動撮影中の画面取得は、圧縮せずに受け取る。
- 画面の取得を2つ並行して行い、コマの届く間隔を約0.3秒にする。
- 並行した取得の結果が前後して届いた場合は、より新しく取得を始めた方の画面だけを使い、古い画面で新しい画面を上書きしない。
- 圧縮しない取得に端末が対応していない場合（受け取ったデータを画面として読めない場合）は、従来の PNG での取得に切り替えて撮影を続ける。
- 保存される画像（PNG）の内容・形式は変えない。
- 手動撮影（[manual-capture.md](../manual-capture.md)）で自動撮影が停止中に行う1回だけの取得は、変更しない。
- iOS の画面取得は変更しない（配信の間隔は go-ios 側で決まり、この修正の対象外）。

## 受入基準（再発防止・回帰テスト）
1. **コマの間隔**: moto g24（USB 接続）で自動撮影中、新しいコマが平均0.4秒以下の間隔で届くこと（動的モードで画面を止めたとき、「📊 静止確認」のログが0.4秒程度の間隔で進むことで確認する）。
2. **止めてから撮影まで**: 再現手順1〜2を行ったとき、操作を止めてから撮影まで3秒以内であること。
3. **コマの順序**: 並行した取得の結果が前後して届いても、古い画面が判定や保存に使われないこと（スクロールを止めた後に、止める前の画面が撮影されないこと）。
4. **保存画像**: 保存された画像が、従来どおり端末の画面と同じ解像度・色の PNG であること（色が入れ替わっていないこと）。
5. **非対応端末での継続**: 圧縮しない取得のデータを画面として読めない場合でも、自動撮影が止まらず、従来の方法で撮影が続くこと。
6. **切断時の扱い**: 撮影中に端末を抜くと、従来どおり切断として扱われ、[LOCAL-017](LOCAL-017_ストリーム接続の一時的な切断で自動撮影全体が停止する.md) の再接続・停止の流れになること。
7. **停止**: 「停止」を押すと、並行している画面取得もすべて止まること（停止後に Android の画面取得が続かないこと）。
8. **回帰**: 静的モード・動的モードの撮影タイミング（[screenshot-capture.md](../screenshot-capture.md)）、撮影中の手動撮影、セッションのまとめ表示が従来どおり動作すること。iOS の撮影に変化がないこと。

## 変更理由
- issue #LOCAL-020: LOCAL-019 の修正後の実機確認で、Android では操作を止めてから撮影まで約5秒かかることを確認した。実機での計測により、原因が画面取得そのものの時間（PNG への圧縮）であると分かった。圧縮しない取得と2並行の取得で、約0.3秒ごとにコマが届くようにする方針をユーザーと合意し、新規作成。
