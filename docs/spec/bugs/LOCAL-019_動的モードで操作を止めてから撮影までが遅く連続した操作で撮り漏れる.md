# バグ修正: 動的モードで、操作を止めてから撮影までが遅く、連続した操作で撮り漏れる

## Issue
#LOCAL-019

## 不具合現象と再現手順（Why）
### 発生している現象
動的モード（[screenshot-capture.md](../screenshot-capture.md)）で端末の操作を止めても、「🎬 画面動作中...」のログがしばらく続く。「📊 静止確認」が始まって撮影されるまで、操作を止めてから5秒以上かかる。iOS と Android の両方で発生する。

また、撮影した直後にすぐ次の画面へ進むと、その画面の撮影が遅れる。次の操作が短い場合は撮影されない（撮り漏れる）。

ユーザーから見ると、設定した「チェック間隔 × 判定回数」（例: 0.1秒 × 3回）よりも撮影がずっと遅く、動作がもっさりして感じられる。

### 再現手順
1. iOS または Android の端末を接続し、動的モード・チェック間隔0.1秒・判定回数3回で自動撮影を開始する
2. 端末で画面をスクロールし、スクロールを止める
3. ログを確認する
   - 期待値: スクロールを止めた後に届いたコマから「📊 静止確認」が始まり、変化の無いコマが判定回数分（3コマ）続いた時点で撮影される
   - 実際: スクロールを止めた後も「🎬 画面動作中...」が2〜3コマ分続き、その後に判定回数分の「📊 静止確認」を経て撮影される。止めてから撮影まで5秒以上かかる
4. 撮影されたらすぐに（1秒以内に）タップして次の画面へ進み、そこで操作を止める
   - 期待値: 次の画面へ進んだ変化が次に届いたコマで検知され、手順3と同じ流れで次の画面も撮影される
   - 実際: 撮影直後の約1秒間は変化の判定が行われない。この間に画面遷移が終わると、次の画面の撮影が遅れるか、撮影されない

## 修正内容（What）
### 根本原因
1. 変化の有無を、直近3コマ分の変化量の平均で判定している。画面が止まっても、動いていたときの大きな変化量が平均に残るため、止まった後の2コマほどが「変化あり」と判定される。
2. 端末から新しい画面が届くのは1秒に1コマ程度（[screenshot-capture.md](../screenshot-capture.md) の既知の制限事項）。そのため、1コマ分の判定の遅れが、そのまま約1秒の遅れになる。1と合わせて、判定回数3回の設定でも、止めてから撮影まで5〜6コマ（5〜6秒）かかる。
3. 撮影した直後の約1秒間は、受け取った画面を捨てて判定をしていない。この間に起きた画面の変化は検知されない。
4. 撮影した画面を比較の基準にするとき、判定時と同じ比較用の画像になっていなかった（サイズが異なる）。そのため撮影後に届いた最初のコマは、変化があっても「変化なし」として基準に置き換わるだけになる。撮影直後に次の画面へ遷移してそのまま止まると、変化が一度も検知されず、その画面は撮影されない。静的モードでも同じ処理を通る。

### 修正方針
- 動的モードでは、各コマの「変化あり／なし」を、そのコマと比較の基準の画面（最後に「変化あり」と判定したコマ、または撮影した画面）との比較だけで決める。過去のコマの変化量を持ち越さない。画面が止まった後の最初のコマの次から「静止確認」を数え始める。
- 動的モードでは、撮影した画面を次の比較の基準とし、撮影の後に届いた最初のコマから判定を再開する。画面を見ない時間を作らない。
- 撮影した画面を比較の基準にするときは、判定時と同じ比較用の画像にする。撮影後に届いた最初のコマも、撮影した画面との変化の有無を正しく判定する（静的モード・動的モード共通）。
- 判定回数の意味（変化の無いコマが何コマ続いたら撮影するか）は変更しない。
- 静的モードの判定方法（変化量の平均の使い方・待ち時間・撮影直後の待ち）は変更しない。変わるのは、上記の撮影後の最初のコマの判定だけ。

## 受入基準（再発防止・回帰テスト）
1. **静止確認の開始**: 再現手順1〜3を行ったとき、スクロールを止めた後の「🎬 画面動作中...」のログは1行以下であること（止まった瞬間のコマの分だけ）。その次に届いたコマから「📊 静止確認: 1/3」が始まること。
2. **撮影までのコマ数**: 受入基準1の後、「📊 静止確認」が 1/3・2/3・3/3 と連続して3行出た時点で撮影されること。静止確認の途中で「🎬 画面動作中...」が挟まらないこと（端末の画面自体が動いていない場合）。
3. **撮影直後の変化検知**: 再現手順4を行ったとき、撮影後に届いた最初のコマで画面遷移が検知され、「🎬 画面動作中...」のログが出ること。遷移先の画面で操作を止めると、受入基準1・2と同じ流れで撮影されること。
4. **撮影後の沈黙の維持**: 撮影した後、画面が変化しない間は、同じ画面が再び撮影されないこと。「📊 静止確認」のログも出ないこと（従来どおり）。
5. **操作中の誤撮影防止**: 端末でスクロールを続けている間は撮影されないこと（[LOCAL-004](LOCAL-004_動的モードのフレーム重複による誤検知.md) の受入基準2と同じ）。
6. **重複フレームの除外の維持**: 新しいコマが届いていない間は、判定が行われないこと（[LOCAL-004](LOCAL-004_動的モードのフレーム重複による誤検知.md) の受入基準1と同じ）。
7. **撮影後の最初のコマの判定**: 動的モードで撮影した後、次に届いたコマが撮影した画面と異なれば「🎬 画面動作中...」と判定されること。同じであれば何も判定されない（ログが出ない）こと。静的モードでも、撮影後の最初のコマが撮影した画面と異なれば「🎬 変化検知...」と判定されること。
8. **回帰（静的モード）**: 静的モードの撮影タイミング（[screenshot-capture.md](../screenshot-capture.md) の受入基準3）が従来どおりであること。
9. **回帰（手動撮影・セッション・再接続）**: 動的モードでの撮影中の手動撮影（[manual-capture.md](../manual-capture.md)）、セッションのまとめ表示（[session-grouping.md](../session-grouping.md)）、切断時の自動再接続（[LOCAL-017](LOCAL-017_ストリーム接続の一時的な切断で自動撮影全体が停止する.md)）が従来どおり動作すること。

## 変更理由
- issue #LOCAL-019: 動的モード（チェック間隔0.1秒・判定回数3回、iOS/Android両方）で、操作を止めてから静止確認に至るまで5秒以上かかる、連続した操作で撮り漏れるという報告を受けて新規作成。判定回数の意味（変化の無いコマ数）は変えず、判定の遅れと撮影直後に画面を見ない時間を解消する方針をユーザーと合意した。
- issue #LOCAL-019: 実装の際、撮影した画面を比較の基準にするとき判定時と同じ比較用の画像になっておらず、撮影後の最初のコマの変化が検知されないことが分かった。撮り漏れの原因の一つであるため、根本原因4として追記し、静的モード・動的モード共通で修正する方針と受入基準7を追加した。
