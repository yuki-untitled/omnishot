# バグ修正: Windows で、絵文字を含むログのコンソール出力に失敗してアプリが落ちる

## Issue
#LOCAL-047

## 不具合現象と再現手順（Why）
### 発生している現象
Windows で OmniShot を起動すると、最初のログ「🚀 OmniShot を起動中...」を出力する時点で `UnicodeEncodeError: 'cp932' codec can't encode character '\U0001f680'` が発生し、アプリが起動できない。Windows のコンソールの文字コード（日本語環境では cp932）が絵文字を表せないため。
ログには絵文字を含むものが多く（撮影完了・警告・終了処理など）、起動後も同じ例外で撮影・終了処理が途中で止まる。

### 再現手順
1. 日本語版 Windows（コンソールの文字コードが cp932）で OmniShot を起動する
2. 起動直後の「🚀 OmniShot を起動中...」のログ出力で例外が発生する
3. 期待値・実際の差異
   - 期待値: ログに絵文字が含まれていても、アプリが起動し、ログ欄に絵文字つきで表示される
   - 実際: 例外でアプリが終了する

## 修正内容（What）
### 根本原因
- ログをコンソールへ出力するとき、コンソールの文字コードで表せない文字（絵文字）が含まれる場合を考慮していない
- 同じ出力は、終了処理・ポート使用中の案内でも行っている

### 修正方針
- コンソールへの出力は、その文字コードで表せない文字があっても例外を投げない。表せない文字は `?` に置き換えて出力する
- コンソールが無い（出力先が存在しない）場合も、例外を投げない
- 画面のログ欄に表示する文字列は変えない（絵文字を含めて従来どおり表示する）
- ログの内容・順序・件数の上限（100件）は変えない

## 受入基準（再発防止・回帰テスト）
1. **再現手順の検証**: コンソールの文字コードが cp932 の環境で、「🚀 OmniShot を起動中...」を出力しても例外が発生せず、アプリが起動すること。
2. **ログ欄の表示**: 絵文字を含むログが、ログ欄に絵文字つきのまま追加されること。
3. **出力先なし**: 標準出力が存在しない環境でも、ログの追加が例外にならないこと。
4. **他の出力箇所**: 終了処理・ポート使用中の案内の出力も、cp932 で絵文字を含んでも例外にならないこと。
5. **回帰**: UTF-8 のコンソールでは、絵文字を含むログが置き換えられずそのまま出力されること。
