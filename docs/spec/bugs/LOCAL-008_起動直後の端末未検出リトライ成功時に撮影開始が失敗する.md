# バグ修正: 端末の初回検出に失敗しリトライで検出できた場合、撮影が開始されず内部エラーで停止する

## Issue
#LOCAL-008

## 不具合現象と再現手順（Why）
### 発生している現象
自動撮影の開始時（[screenshot-capture.md](../screenshot-capture.md)）、端末接続の直後などで1回目の端末検出では端末が見つからず、1秒後の再検出で端末が見つかった場合に、撮影が開始されず内部エラーで停止する。ユーザーには「ストリームの開始に失敗しました」等の分かりやすい案内は出ず、撮影が始まらない。

### 再現手順
1. 端末（iOSまたはAndroid）をUSB接続した直後、端末が認識される前のタイミングで「自動撮影開始」を押す
2. 1回目の検出では端末が見つからず、1秒後の再検出で端末が見つかる状況にする
3. 期待値・実際の差異
   - 期待値: 再検出で見つかった端末で撮影が開始される
   - 実際: 撮影が開始されず、内部エラー（リストの範囲外参照）で撮影ループが停止する

## 修正内容（What）
### 根本原因
- 再検出の結果を、1回目の検出結果とは別の変数に格納しており、その後の「使用する端末の決定」が1回目の（空の）検出結果を参照している

### 修正方針
- 再検出で端末が見つかった場合は、その結果を使用する端末の決定に用いる
- 再検出でも端末が見つからない場合は、従来通り「デバイスが検出されませんでした」のメッセージを表示して停止する

## 受入基準（再発防止・回帰テスト）
1. **再検出成功時**: 1回目の検出で端末が0台、再検出で1台以上の場合、再検出で見つかった端末で撮影が開始されること。
2. **再検出失敗時**: 1回目・再検出ともに端末が0台の場合、「デバイスが検出されませんでした」のメッセージが表示され、撮影が開始されないこと。内部エラーで停止しないこと。
3. **回帰（初回検出成功）**: 1回目の検出で端末が見つかった場合、従来通り再検出を行わずに撮影が開始されること。
