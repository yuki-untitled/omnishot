# バグ修正: ログ表示欄で、HTMLを含む文字列がHTMLとして解釈されてしまう

## Issue
#LOCAL-010

## 不具合現象と再現手順（Why）
### 発生している現象
画面のログ表示欄（[screenshot-capture.md](../screenshot-capture.md) の撮影ログ、[gallery.md](../gallery.md) の表示名変更ログ）は、サーバーから受け取ったログの文字列をHTMLとして解釈して表示している。ログには、ユーザーが入力した表示名やエラーメッセージが含まれるため、`<` や `>` を含む表示名を設定すると、ログ欄で文字列として表示されず、HTMLとして解釈される（表示の崩れ、意図しないスクリプトの実行）。

### 再現手順
1. ギャラリーで任意の画像の表示名を `<b>test</b>` に変更する
2. ログ表示欄に出力される「表示名を変更しました」のログを確認する
3. 期待値・実際の差異
   - 期待値: `<b>test</b>` という文字列がそのまま表示される
   - 実際: `<b>` が解釈され、`test` が太字で表示される（`<img onerror=...>` のようなHTMLを設定した場合は、その内容が実行される）

## 修正内容（What）
### 根本原因
- ログ表示欄への出力時に、ログ文字列のHTML特殊文字を文字として扱うための変換を行っていない（ギャラリーの表示名表示には変換がある）

### 修正方針
- ログ表示欄では、ログの文字列をすべて文字として表示する（HTMLとして解釈しない）
- ログの内容・順序・件数の上限（画面に表示する最新50件）は変えない

## 受入基準（再発防止・回帰テスト）
1. **再現手順の検証**: 表示名を `<b>test</b>` に変更した際、ログ表示欄に `<b>test</b>` という文字列がそのまま表示されること。
2. **スクリプト非実行**: 表示名に `<img src=x onerror=alert(1)>` を設定しても、スクリプトが実行されないこと。
3. **回帰（通常ログ）**: 絵文字を含む撮影ログ（「📸 撮影完了: …」等）が従来通り新しい順に表示され、撮影完了でギャラリーが更新されること。
