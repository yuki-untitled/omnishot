# バグ修正: 起動直後、設定ガイドのタブ（iOS / Android）が最初のクリックでは切り替わらない

## Issue
#LOCAL-012

## 不具合現象と再現手順（Why）
### 発生している現象
アプリ起動時に自動表示されていた設定ガイド（[native-window.md](../native-window.md) のネイティブウィンドウ内に表示される画面）で、「iPhone (iOS) の設定」「Android の設定」のタブを最初にクリックしても切り替わらず、ダブルクリック（2回目のクリック）で初めて切り替わる。起動直後の最初の操作でのみ発生し、2回目以降の操作では1クリックで切り替わる。

設定ガイドの起動時の自動表示は [LOCAL-013](LOCAL-013_設定ガイドの次回から表示しないを廃止し起動時の自動表示をやめる.md) で廃止するが、原因が「起動直後の最初のクリック」全般にある場合、自動表示の廃止後も、最初にクリックした操作（例: 「設定ガイド」ボタン）が効かない状態が残る。そのため、本不具合は自動表示の廃止後も対象とする。

### 再現手順
1. Mac で `python3 run.py` によりアプリを起動する（ターミナルまたは IDE にフォーカスがある状態）
2. ウィンドウ内の最初の操作として、設定ガイドのタブ（「Android の設定」。自動表示の廃止後は「設定ガイド」ボタン）を1回だけクリックする
3. 期待値・実際の差異
   - 期待値: 1回のクリックで操作が効く（Android の設定手順に切り替わる、またはガイドが開く）
   - 実際: 効かない。もう一度クリックすると効く

## 修正内容（What）
### 根本原因
- 起動元のアプリ（ターミナルや IDE）がフォーカスを持ったまま起動されると、ネイティブウィンドウが「操作を受け付ける状態（アクティブ）」にならないことがある。この状態のウィンドウへの最初のクリックは、ウィンドウの有効化にだけ使われ、画面の操作として受け付けられない。
- 確認できた事実: 使用中の pywebview（6.2.1）の Mac 用ウィンドウは、非アクティブなウィンドウへの最初のクリックを画面に渡さない設定になっている。
- 未確認の点: 起動元がフォーカスを持つ状態での実機での再現。開発時の確認環境では、起動直後のウィンドウはアクティブだった。

### 修正方針
- 起動後、ウィンドウを開いた直後の最初のクリックから、画面上の操作（タブの切り替え、ボタン、チェックボックスなど）が受け付けられる状態にする。
- ガイドの内容・タブの見た目は変えない。

## 受入基準（再発防止・回帰テスト）
1. **再現手順の検証**: 再現手順を実行したとき、最初の1回のクリックで操作が効くこと。起動直後に「設定ガイド」ボタンを1回クリックしてガイドが開き、iOS タブ→Android タブ→iOS タブの順にクリックして、各クリック1回で切り替わること。
2. **起動元がフォーカスを持つ場合**: ターミナルまたは IDE からアプリを起動し、そのアプリにフォーカスがある状態でも、ウィンドウ内の最初のクリックが有効であること。
3. **回帰（ガイド以外の操作）**: ガイドを閉じた後のギャラリー・撮影ボタン・設定入力が、従来どおり1クリックで操作できること。
4. **回帰（ウィンドウを閉じた際の後始末）**: ウィンドウの閉じるボタンでの後始末が、従来どおり行われること（[native-window.md](../native-window.md) 受入基準2）。
