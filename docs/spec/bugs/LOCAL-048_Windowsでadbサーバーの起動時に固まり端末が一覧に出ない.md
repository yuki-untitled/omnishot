# バグ修正: Windows で、adb サーバーの起動時に処理が固まり、Android 端末が一覧に出ない

## Issue
#LOCAL-048

## 不具合現象と再現手順（Why）
### 発生している現象
Windows 版の OmniShot で、Android 端末を USB で接続しても、端末が一覧に表示されない。端末側には USB デバッグの許可ダイアログが出て許可もできる（adb サーバーは起動し、端末ともつながっている）。

### 再現手順
1. Windows で、adb サーバーが動いていない状態にする（アプリは終了時に adb サーバーを止めるため、起動のたびにこの状態になる）
2. Android 端末を USB で接続し、OmniShot を起動する（または設定ガイドの USB デバッグの許可の操作をする）
3. 期待値・実際の差異
   - 期待値: Android 端末が一覧に表示される
   - 実際: 端末が一覧に表示されない

## 修正内容（What）
### 根本原因
- adb は、サーバーが動いていないとき、常駐するサーバーを子プロセスとして起動する。この子プロセスが、親（adb のコマンド）の出力用パイプを持ったまま残る
- 出力をパイプで受け取る実行（`capture_output`）は、Windows では出力の終わりを待ち続けてタイムアウトする（検出は 5 秒、サーバーの起動し直しは 10 秒）
- 例外は握りつぶされ、ウィンドウアプリのためコンソールにも出ず、端末が 0 台に見える

### 修正方針
- adb サーバーの起動（`adb start-server`）は、出力をパイプではなく一時ファイルで受け取って実行する。サーバーを起動した旨のメッセージ（`daemon started successfully`）は従来どおり検出に引き継ぐ
- 端末の検出は、先にこの方法でサーバーを起動してから `adb devices -l` を実行する
- adb サーバーの起動し直し（USB デバッグの許可ダイアログを出し直す操作）も、同じ方法で起動する
- 起動直後に端末が見つからなければ 1 秒待って 1 回だけ検出し直す仕様（[native-window.md](../native-window.md)）は変えない

## 受入基準（再発防止・回帰テスト）
1. **再現手順の検証**: Windows で adb サーバーが動いていない状態からアプリを起動し、接続して許可済みの Android 端末が、最初の検出で一覧に表示されること（実機で確認）。
2. **パイプを使わない起動**: adb サーバーの起動は、標準出力・標準エラー出力にパイプを使わずに実行されること。
3. **起動直後の検出し直し**: サーバーを起動した旨のメッセージが検出の結果に引き継がれ、端末が見つからなければ 1 回だけ検出し直すこと。
4. **起動し直し**: adb サーバーの起動し直しは、停止してから、パイプを使わずに起動すること。
