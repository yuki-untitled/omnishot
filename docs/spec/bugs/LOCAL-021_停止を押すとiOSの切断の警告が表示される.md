# バグ修正: 自動撮影の「停止」を押すと、iOS の切断の警告が表示される

## Issue
#LOCAL-021

## 不具合現象と再現手順（Why）
### 発生している現象
iOS 端末で自動撮影をしているときに「停止」を押すと、ログ欄に「⚠️ iOS device disconnected: IncompleteRead(...)」という切断の警告が表示される。ユーザーが自分で止めただけなのに、端末との接続に問題が起きたように見える。本当の切断（ケーブルが抜けた、go-ios が異常終了した、など）の警告と見分けがつかない。

### 再現手順
1. iOS 端末を接続し、自動撮影を開始する（モードは問わない）
2. 「停止」を押す
3. ログを確認する
   - 期待値: 「🔌 ストリーム接続を閉じました」だけが表示され、切断の警告は表示されない
   - 実際: 「⚠️ iOS device disconnected: IncompleteRead(2538 bytes read)」が表示され、その後に「🔌 ストリーム接続を閉じました」が表示される

## 修正内容（What）
### 根本原因
- 停止すると、アプリは画面の受信を止めてから go-ios を終了する。受信中の通信は go-ios の終了によって途中で切れ、エラーになる。
- iOS の受信処理は、通信のエラーが停止によるものか、本当の切断によるものかを区別せず、すべて切断として警告を表示していた。
- Android の受信処理は、[LOCAL-020](LOCAL-020_Androidの画面取得に1コマ約1秒かかり自動撮影の反応が遅い.md) の修正で、停止によるエラーでは警告を出さないようになっている。iOS だけが対応していなかった。

### 修正方針
- ユーザーが停止した後に起きた受信のエラーは、切断として扱わず、警告も表示しない。
- 撮影中（停止していない間）に起きた受信のエラーは、従来どおり切断として警告を表示し、[LOCAL-017](LOCAL-017_ストリーム接続の一時的な切断で自動撮影全体が停止する.md) の再接続・停止の流れに進む。

## 受入基準（再発防止・回帰テスト）
1. **停止時に警告を出さない**: 再現手順1〜3を行ったとき、ログに「⚠️ iOS device disconnected」が表示されないこと。「🔌 ストリーム接続を閉じました」は従来どおり表示されること。
2. **本当の切断では警告を出す**: iOS で撮影中に go-ios が終了した場合や、ケーブルを抜いた場合は、従来どおり「⚠️ iOS device disconnected」が表示され、再接続（ログに「🔄 接続を再開しました」）または停止の流れになること。
3. **Android の回帰**: Android で撮影中に「停止」を押しても、「⚠️ Android device disconnected」が表示されないこと（従来どおり）。
4. **撮影の回帰**: 停止の後に再び自動撮影を開始すると、従来どおり撮影できること。
