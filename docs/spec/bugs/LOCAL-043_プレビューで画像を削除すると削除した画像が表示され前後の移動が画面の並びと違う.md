# バグ修正: プレビューで画像を削除すると削除した画像が表示され、前後の移動が画面の並びと違う

## Issue
#LOCAL-043

## 不具合現象と再現手順（Why）
### 発生している現象
1. **削除した画像が表示される。** プレビューで画像を削除すると、削除した直後に、削除したはずの画像（または、壊れた画像）が表示されることがある。
2. **前後の移動が、画面の並びと違う。** プレビューの前後の矢印（と、キーボードの左右の矢印）は、撮影が新しい順の全画像の並びで進む。ギャラリーの画面の並び（並び順設定、セッションごとのまとまり、手動の並べ替え、端末の絞り込み）とは、順序が違う。次の画像を見ようとすると、画面で隣にある画像とは別の画像が表示される。端末の絞り込みで隠れている画像も、プレビューに現れる。

### 再現手順
1. 画像が3枚以上あるギャラリーで、真ん中の画像をクリックしてプレビューを開く。
2. プレビューの削除ボタンを押し、確認メッセージで確定する。
3. 期待値: 削除した画像が消え、隣の画像が表示される。実際: 削除した画像、または壊れた画像が表示されることがある。
4. 別の再現: セッションが2つあり、並び順が「古い順」のとき、1つ目のセッションの最後の画像をプレビューで開き、「次」を押す。期待値: 画面で次に並んでいる、2つ目のセッションの先頭の画像。実際: 撮影が新しい順の全画像の並びで、別の画像が表示される。
5. 別の再現: 端末の絞り込みを「iOS のみ」にして、プレビューを開き、前後に移動する。期待値: iOS の画像だけを移動する。実際: 隠れている Android の画像にも移動する。

## 修正内容（What）
### 根本原因
- 1: プレビューの削除の後、ギャラリーの再取得は完了を待たずに、プレビューの次の画像を選んでいる。そのため、まだ削除前のままの画像の一覧を使って、次の画像を選んでいる。
- 2: プレビューが、画像の並びとして、撮影が新しい順の全画像の一覧を使っている。ギャラリーが画面に表示している並び（絞り込み・並び順・セッションごとのまとまり・手動の並べ替えを反映した並び）とは、別の一覧。

### 修正方針
- プレビューの前後の移動と、「N / 全体の枚数」の表示は、ギャラリーが画面に表示している並びに従う。
  - 端末の絞り込みで隠れている画像は、移動の対象にも、枚数にも含めない。
  - 並び順設定（新しい順・古い順）・セッションごとのまとまり（未分類は末尾）・セッション内の手動の並べ替えも、画面の並びと同じにする。
- プレビューで画像を削除したときは、削除した画像を表示せず、画面の並びで次の画像を表示する。削除した画像が画面の並びの最後だったときは、前の画像を表示する。画像が1枚もなくなったときは、プレビューを閉じる。

## 受入基準（再発防止・回帰テスト）
1. **削除後の表示**: 画像が3枚以上あるとき、真ん中の画像をプレビューで削除すると、削除した画像や壊れた画像が表示されず、画面の並びで次の画像が表示されること。最後の画像を削除すると前の画像が、1枚だけの状態で削除するとプレビューが閉じること。
2. **枚数の表示**: 削除後の「N / 全体の枚数」が、削除後の画面の並びと一致すること。
3. **前後の移動**: セッションが2つあるとき、プレビューの「次」「前」が、画面で隣に並んでいる画像へ移動すること。並び順が「新しい順」「古い順」のどちらでも、また、セッション内で手動の並べ替えをした後でも同じであること。セッションをまたいで移動できること。
4. **絞り込み**: 端末の絞り込みを「iOS のみ」にしているとき、プレビューの前後の移動と枚数の表示が、iOS の画像だけになること。
5. **キーボード**: キーボードの左右の矢印による移動も、同じ並びに従うこと。
6. **回帰**: プレビューの表示・閉じる・ダウンロード・削除、ギャラリーの選択・削除が従来どおり動作すること。
