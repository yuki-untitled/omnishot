# バグ修正: アプリ化（.app）すると iOS のトンネルが起動できず、トンネルの起動が連鎖し続ける

## Issue
#LOCAL-032

## 不具合現象と再現手順（Why）
### 発生している現象
PyInstaller でビルドした OmniShot.app を Finder から起動すると、iOS 17 以降の端末を撮影できない。

- 撮影を始めると「failed starting mjpeg」が表示され、撮影が始まらない。
- go-ios の常駐トンネル（`go-ios tunnel start --userspace`）が約1秒で終了しては、次のトンネルを起動する。この連鎖が続き、常に14〜15個のプロセスが動く。1個あたり CPU を30〜50%使い、Mac 全体が重くなる。
- 連鎖しているトンネルのプロセスは、親がアプリではない（親は PID 1）。そのため、アプリを閉じても連鎖は止まらない。

開発時の実行（リポジトリの直下で `python run.py`）では起きない。

### 再現手順
1. go-ios のトンネルが動いていない状態にする（例: アプリを終了した直後。LOCAL-026 により終了時にトンネルは止まる）
2. iOS 17 以降の端末を USB で接続し、Finder から OmniShot.app を起動する
3. 端末を選んで「自動撮影」または「手動撮影」を押す
   - 期待値: トンネルが起動して撮影が始まる
   - 実際: 「failed starting mjpeg」が表示される。go-ios のトンネルのプロセスが起動と終了を繰り返し続け、アプリを閉じても止まらない

## 修正内容（What）
### 根本原因
次の2つが重なっている。

1. **go-ios は、トンネル用の自分の識別情報のファイル（`selfIdentity.plist`）を作業フォルダに作る。** Finder から起動した .app は作業フォルダが `/` で書き込めないため、トンネルの起動に失敗する。開発時は作業フォルダがリポジトリの直下で書き込めるため、起きない（リポジトリの `.gitignore` とビルド手順に `selfIdentity.plist` があるのはこのため）。
2. **アプリは go-ios に「トンネルが無ければ自動で起動する」設定（`ENABLE_GO_IOS_AGENT`）を付けて呼び出し、起動されたトンネルもこの設定を引き継ぐ。** 起動に失敗したトンネルは、引き継いだ設定によって次のトンネルを起動してから終了する。これが連鎖する。

以前は開発時に起動したトンネルが残っていて、.app はそれを使えていた。LOCAL-026 で終了時にトンネルを止めるようになってからは、.app が自分でトンネルを起動する必要があり、表に出た。

実機（Mac・iPhone SE 第3世代・go-ios 1.3.2）で、連鎖しているトンネルのプロセスの作業フォルダが `/` であること、`ENABLE_GO_IOS_AGENT=user` を引き継いでいること、`selfIdentity.plist` がどこにも作られていないことを確認した。

### 修正方針
- アプリが go-ios を呼び出すときは、どこから起動しても、作業フォルダをユーザーごとのアプリ用フォルダにする。
  - Mac: `~/Library/Application Support/OmniShot`
  - Windows: `%APPDATA%\OmniShot`
  - フォルダが無ければアプリが作る。開発時の実行でも同じフォルダを使う。
- トンネル用の識別情報のファイルは、アプリを終了しても消さない。次に起動したときも同じ識別情報を使うため。
- 保存先が変わるため、修正後の初回だけ、端末とのペアリングをやり直すことがある（端末に「このコンピュータを信頼しますか？」が表示されたら「信頼」を押す）。

## 受入基準（再発防止・回帰テスト）
1. **再現手順の検証**: トンネルが動いていない状態で、Finder から OmniShot.app を起動し、iOS 17 以降の端末で「自動撮影」を押すと、「failed starting mjpeg」が表示されずに撮影が始まること。「手動撮影」でも撮影できること。
2. **連鎖が起きない**: 受入基準1の操作中と操作後に、go-ios のトンネルのプロセスが1個以下であること。
3. **識別情報の保存先**: 受入基準1の後、`~/Library/Application Support/OmniShot/selfIdentity.plist` があること。アプリを終了しても残っていること。
4. **回帰（終了時の後始末）**: iOS 端末で撮影した後にアプリを終了すると、トンネルのプロセスが残っていないこと（[native-window.md](../native-window.md) の受入基準5、[LOCAL-030](LOCAL-030_終了時にiOSのトンネルが動いていないとトンネルが起動して残る.md) の受入基準1・2）。
5. **回帰（開発時の実行）**: リポジトリの直下で `python run.py` を実行したときも、iOS 端末・Android 端末で撮影できること。
6. **回帰（Windows）**: Windows の OmniShot.exe で、iOS 端末で撮影できること（未確認の LOCAL-005 と合わせて確認する）。
