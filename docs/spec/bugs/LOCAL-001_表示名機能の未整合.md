# バグ修正: ギャラリーの表示名変更がサーバー側に永続化されず、ZIPダウンロードにも反映されない

## Issue
#LOCAL-001

## 不具合現象と再現手順（Why）
### 発生している現象
1. ギャラリーで画像の表示名を編集すると、フロントエンド（[main.js](../../../static/js/main.js)）は `POST /rename` にリクエストを送るが、バックエンド（[app.py](../../../app.py)）に対応するルートが存在しないため 404 になる。エラーハンドリングが無いため画面上は何も起きたように見えない。表示名はブラウザの `localStorage` にのみ保存され、サーバーには一切永続化されない。
2. 選択画像をZIPダウンロードする際、フロントエンドは `nameMap`（元ファイル名→表示名の対応）と `zipName`（ユーザーが入力したZIPファイル名）をリクエストボディに含めて送信するが、`download_selected` エンドポイントはこれらを読み取らず、常に元のファイル名でZIPに格納し、ZIPファイル名も固定書式（`captures_{タイムスタンプ}.zip`）で生成している。

### 再現手順
1. 自動撮影で画像を1枚以上撮影し、ギャラリーに表示させる
2. ギャラリー上の画像のファイル名表示部分をクリックし、任意の表示名を入力してEnterで確定する
3. ブラウザの開発者ツール Network タブを確認する
   - 期待値: `POST /rename` が成功（200系）する
   - 実際: `POST /rename` が 404 を返す
4. 表示名を変更した画像を選択し、「ダウンロード」ボタンからZIPファイル名を指定してダウンロードする
5. ダウンロードされたZIPを展開する
   - 期待値: ZIP内のファイル名が手順2で設定した表示名（.png付き）になっており、ZIPファイル自体のファイル名も手順4で入力した名前になっている
   - 実際: ZIP内のファイル名は元のファイル名（例: `Android_20250917_120000.png`）のままで、ZIPファイル名も入力値が無視され自動生成された名前になる

## 修正内容（What）
### 根本原因
- フロントエンドの表示名編集機能の実装が先行し、対応するバックエンドの永続化エンドポイント（`/rename`）が実装されないまま残っている
- `download_selected` がリクエストボディの `nameMap` / `zipName` を利用しない実装になっており、表示名編集機能とダウンロード機能が連携していない

### 修正方針
- 表示名の変更は、対象のキャプチャファイル（ファイル名）に紐づけてサーバー側にも永続化し、`localStorage` を消去したり、別のブラウザ・別端末からアクセスした場合、あるいはアプリ再起動後でも、同じキャプチャファイルには同じ表示名が復元されるようにする
- 表示名の紐付けはファイル名をキーとして一意に行う（表示名の文字列同士の前後比較には依存しない）
- ギャラリー表示・ダウンロードのいずれの経路でも、サーバー側に保存された表示名が使われる状態にする
- ZIPダウンロード時は、選択された各ファイルについて設定済みの表示名（未設定の場合は元のファイル名）をZIP内のファイル名として使用する
- ZIPダウンロード時、ユーザーが入力したZIPファイル名をダウンロードファイル名として使用する（未入力・空の場合は従来通り自動生成名にフォールバックする）
- キャプチャファイルが削除された場合、対応する表示名の永続化データも整合性が取れた状態（不要なデータが残り続けない）になるようにする

## 受入基準（再発防止・回帰テスト）
1. **表示名の永続化**: 画像の表示名を変更した後、ブラウザの `localStorage` を消去してページを再読み込みしても、変更した表示名がギャラリーに表示されること。
2. **表示名の永続化（再起動）**: 表示名を変更した後にサーバーアプリケーションを再起動しても、対象のキャプチャファイルが存在する限り、変更後の表示名が復元されること。
3. **ZIP内ファイル名の反映**: 表示名を変更した画像を選択してダウンロードすると、生成されたZIP内の各ファイルのファイル名が、変更後の表示名（.png拡張子付き）になっていること。
4. **ZIPファイル名の反映**: ダウンロード時に入力したZIPファイル名が、実際にダウンロードされるファイルの名前として使用されること。空入力の場合は従来通り自動生成された名前が使われること。
5. **回帰（未編集画像）**: 表示名を変更していない画像は、従来通り元のファイル名でギャラリー表示・ダウンロードされること。
6. **回帰（混在選択）**: 表示名を設定した画像と未設定の画像が混在した状態での複数選択ダウンロードが、エラーなく完了すること。
7. **回帰（既存機能）**: プレビューモーダルでの削除・ダウンロード、全選択・全解除、選択削除、デバイスフィルタ・ソートなど、表示名機能に関連しない既存のギャラリー機能が引き続き正常に動作すること。
8. **回帰（削除との整合性）**: 表示名を設定した画像を削除した後、同名の表示名を持つ別ファイルが誤って表示されないこと。
